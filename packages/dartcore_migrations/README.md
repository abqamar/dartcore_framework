# dartcore_migrations

Schema builder, versioned migrations, seeders and a console runner for DartCore on PostgreSQL, MySQL and SQLite.

Part of [DartCore](https://github.com/abqamar/dartcore_framework), a pure-Dart backend SDK. Projects generated by `dartcore create` already wire this up.

## Install

```sh
dart pub add dartcore_migrations
```

You also need `dartcore_db` and a database adapter (`dartcore_postgres`, `dartcore_mysql` or `dartcore_sqlite`).

## Usage

```dart
import 'package:dartcore_db/dartcore_db.dart';
import 'package:dartcore_migrations/dartcore_migrations.dart';

class CreateUsersTable extends Migration {
  @override
  String get id => '2025_01_31_120000_create_users_table';

  @override
  Future<void> up(SchemaBuilder schema) => Schema.create('users', (table) {
        table.id();
        table.string('name');
        table.string('email').unique();
        table.boolean('active').defaultValue(true);
        table.timestamps();
      });

  @override
  Future<void> down(SchemaBuilder schema) => Schema.dropIfExists('users');
}

// After registering an adapter and calling DB.connect(...):
final migrator = Migrator(DB.connection(), [CreateUsersTable()]);
await migrator.migrate();      // runs pending migrations as one batch
await migrator.status();
await migrator.rollback();     // last batch
```

Seeders extend `Seeder` and implement `run()`. `MigrationConsole` provides the command-line runner behind
`dartcore migrate`, `migrate:rollback`, `migrate:reset`, `migrate:fresh`, `migrate:status` and `db:seed`;
destructive commands ask for confirmation and refuse to run in production without `--force`.

The runnable [example](https://github.com/abqamar/dartcore_framework/blob/main/packages/dartcore_migrations/example/dartcore_migrations_example.dart) runs on SQLite `:memory:`.

## Status and limits

Pre-1.0: the API may change. Unsupported schema changes throw instead of being emulated: on SQLite `.change()` and adding a
UNIQUE or foreign-key column to an existing table are not supported. **MySQL DDL is not transactional**, so a failing
migration may be partly applied (PostgreSQL and SQLite run each migration in a transaction). There is no migration lock:
run migrations from one place, such as a deploy step. See the [migrations guide](https://github.com/abqamar/dartcore_framework/blob/main/docs/migrations.md).
